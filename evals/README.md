# evals/

The adversarial suite. Owned by Track B.

```bash
cargo test -p airlock-evals
```

Runs entirely offline against stub mode — no API key, no network, no second
process. It is a pre-merge check, not something we only remember to run when
a key is loaded.

## What it covers

| File | Asserts |
|---|---|
| `tests/scams.rs` | Every case in the scam corpus holds, and the corpus still spans the families the README names. |
| `tests/injection.rs` | Messages instructing the Reader to report "safe" change nothing — plus the structural proof below. |
| `tests/fail_closed.rs` | A Reader that is dead, hanging, panicking or returning garbage produces `Unavailable`, never a passing verdict. |
| `tests/false_positives.rs` | Measures the false-positive rate on the legitimate corpus and rewrites `measured.md`. |

## The corpus

`fixtures/` holds three files with identical shape, so the legitimate half is
visibly graded the same way as the scam half:

- `scams.json` — fake telco agent, wrong-transfer refund, prize release fee,
  fake loan officer, safe-account, NIN fee, utility disconnection, M-Pesa
  reversal, MD impersonation.
- `injection.json` — direct instruction to report safe, fake `<system>` tags,
  a polite note to "any AI reviewing this", a JSON payload in the body, a
  fake policy-engine override, and a message claiming the recipient is
  already trusted.
- `legitimate.json` — ordinary traffic, including the family-emergency
  transfer to a new number that the demo shows being held on purpose.

Add cases by editing JSON. No Rust changes needed.

## The injection result worth reading

The corpus tests are behavioural: they show *these* payloads failed.
`the_linker_never_receives_free_text` is the one that generalises.

`PressureSignal` has three attacker-influenceable free-text fields —
`authority_claim`, `RequestedAction::Other(_)` and `MaskedMsisdn`. Sanitising
them is the first layer. The second is that the Linker never receives them at
all: it takes a `LinkerView`, which contains no `String` and no variant
carrying one. Whether the message named this transfer's amount or recipient
is computed in Rust and handed over as a `FactMatch` enum.

The test stuffs every field a compromised Reader controls with an attack
string, projects it, serialises the result, and asserts none of the payload
appears. That is a property of the type, not a property of the sample.

The complementary result is that a Reader lying in the *other* direction —
claiming a match that isn't there — can only cause a hold. There is no lie it
can tell that produces a pass.

## False positives

`measured.md` is regenerated by the test run; don't edit it by hand.

Airlock holds genuine first-time transfers. That is inherent to judging
novelty, not a defect to tune away, so a legitimate case that holds is not a
test failure — the test fails when the rate drifts past `CEILING`.

The rate moved once already and it is worth knowing why. The first version
treated an exact amount or recipient match as responsive on its own, and held
"Invoice attached for the office supplies, N45,000" and "Thanks for lunch! My
number is 08111222333" — 40% of the legitimate corpus. Those are not scam
behaviour; that is what arranging a payment looks like. Urgency now gates
responsiveness, which is what the README says the whole design rests on:
remove the hurry and most of these collapse. Correspondence alone is not
responsiveness.

Read the current figure with the caveat printed alongside it: the corpus is
small and written by the same people who wrote the rules it grades.
